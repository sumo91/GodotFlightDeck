# Mission Brief：对已保存脚本获得可信的编辑器级诊断

## Outcome

Agent 能通过 GDeck CLI 对目标项目中指定的已保存 GDScript 获得编辑器级错误、警告和源码位置，在修改后直接定位目标脚本及相关依赖问题，并知道本次诊断是否完整、时间花在哪里。

## Success

- 诊断使用项目实际选用的 Godot 引擎和相关项目配置，返回目标脚本的编辑器级错误与警告，而不止加载、编译是否成功。
- 结果包含严重程度、可理解的问题描述、源码文件和引擎可提供的位置；区分目标脚本问题、相关依赖问题与诊断执行故障，不把依赖错误错挂到目标文件。
- 对目标脚本给出明确的检查完成状态。只有所需上下文完整且检查完成、未发现错误或警告时，才可声称“无诊断”；启动失败、超时、上下文缺失或结果未收齐不能成为干净结果。
- 输出准备、启动、检查和总耗时，说明各阶段的计量边界；以实际项目测量解释成本，不承诺比现有检查更快。
- CLI 用法可发现，结果能被 Agent 消费；现有 `check --file` 仍可作为轻量加载、编译检查使用，已有改进保持有效。

## Evidence Required

- 在真实项目的隔离环境中，选择有代表性的已保存脚本，覆盖正常脚本、目标脚本错误、仅警告、相关依赖错误及项目上下文引用。与同一引擎和配置下的编辑器诊断对照，核对问题、严重程度和源码位置。
- 完成一次“修改脚本 → 查询诊断 → 按位置修正 → 再次诊断”的实际 CLI 闭环，证明结果随当前磁盘内容更新；保留正反两轮证据。
- 验证诊断未完整完成的情况，至少覆盖执行中断或超时，以及缺失所需上下文，确认结果不误报干净。验证依赖错误的归属，并保留可复现样本。
- 在同一项目、引擎和目标脚本上测量新诊断与现有 `check --file` 的耗时；记录准备、启动、检查、总耗时及冷暖状态、缓存等影响条件。说明两者诊断深度不同，不能将耗时差直接归因于优化。
- 按实际改动回归现有 `check --file` 的正常、错误和项目上下文引用路径，以及受影响的 CLI/报告行为。说明未覆盖的平台或诊断类型。
- Mission 判定：诊断准确、完整性判定可信、计时可解释且兼容性有证据为 `PASSED`；漏掉应出现的问题、位置错误、误报干净或破坏既有行为为 `FAILED`；缺少对照或关键检查未完成为 `INCONCLUSIVE`。此判定评价工具能力；正确发现脚本错误本身是通过证据。

## Boundaries

- 首轮针对已保存的 GDScript，交付编辑器级定向诊断；未保存编辑器缓冲区和其他脚本语言不在范围内。
- 诊断质量优先，速度实测，不设必须加速的门槛，也不以删减必要项目上下文换取表面提速。
- 本 Mission 独立于[内置类 API 查询](../builtin-class-info/brief.md)，没有约定的交付顺序。
- 保留现有 `check --file` 的轻量用途和 CLI 优先行为。MCP、Pi 新接口和全局安装更新不是本 Mission 的必需交付。
- 验证保留原项目改动，使用隔离环境和测试数据，不使用真实玩家存档。功能不承担自动修复项目错误或全库重构。
- 诊断后端、隔离机制、进程复用、命令参数及单次请求规模由执行者决定；结果须如实表达实际覆盖范围和完整性。

## Context

**Authority Sources：**用户依次选择“诊断质量优先，速度实测”“编辑器级定向诊断”，随后明确“两项各创建一份独立 Brief”；此前已接受常规工作 CLI 优先、MCP 可选，并要求保留已有改进。本文保存这些决定对本 Mission 的有效约束。

**Reference Sources：**以下是执行起点，不是固定实现要求。

- 创建时仓库为 `ece9c24`，版本 `1.6.8`。当前[CLI](../../../cli/gdeck.mjs)的 `checkScriptFile` 直接在项目上下文启动[加载脚本](../../../godot/check_script_runner.gd)，根据进程状态和错误输出判断结果；此直接路径没有准备临时项目副本，也不等同于编辑器级诊断。
- 现有加载脚本通过 `SceneTree` 建立项目上下文，以支持 autoload 引用；应在相关回归中保留这一能力，不能只用独立无依赖脚本证明兼容。
- [现有诊断提示](../../../cli/diagnostics.mjs)用于定位日志证据，并非完整的编辑器诊断结果或独立的 Verdict 依据。新能力应保持诊断内容、执行完整性和验收结论的区别。
- [GDeck 使用指引](../../../skills/godot-flight-deck/SKILL.md)和[README](../../../README.md)提供现行入口与兼容目标。已有真实项目 GreyRanger 可用于实测，具体检出和样本由执行者选择并记录。
