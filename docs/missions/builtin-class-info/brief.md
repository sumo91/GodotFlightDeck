# Mission Brief：查询项目实际引擎的内置类 API

## Outcome

Agent 能通过 GDeck CLI 的 `class-info` 查询目标项目实际选用的 Godot 引擎内置类 API，据此选择可用的方法、参数、属性和信号，理解继承关系，减少依赖其他引擎版本知识造成的调用错误。

## Success

- 查询结果绑定本次实际解析到的 Godot 可执行文件与版本，沿用 GDeck 现有引擎选择规则。
- 能查询内置引擎类的方法及参数、属性、信号和继承关系；引擎提供的类型、默认参数和返回值信息足以支持实际调用。结果能区分本类声明与继承成员。
- CLI 用法可发现，结果能被 Agent 消费；未知类、超出范围的类、引擎不可用与元数据缺失具有明确含义，不伪装成完整的空结果，也不补造 API 信息。
- 现有命令及本地已接受的改进保持有效，常规查询不依赖 MCP 连接。

## Evidence Required

- 在 GreyRanger 实际选用的 Godot 引擎下，从 CLI 完成一次“查询 API → 据此编写或修正最小脚本 → 使用同一引擎验证调用”的闭环，保留命令、引擎身份、查询结果和验证结果。
- 用代表性内置类覆盖上述成员类型、默认参数及继承关系，逐项与该引擎的实际信息核对；仅验证固定 JSON 形状不能证明 API 正确。
- 验证引擎配置与显式覆盖的选择行为，记录最终执行对象；覆盖未知类、范围外类，以及无法获得完整信息的失败路径，确认没有误报完整成功。
- 按实际改动运行相关 CLI 参数解析、引擎选择和现有查询路径的回归，说明覆盖范围。
- Mission 判定：上述结果与兼容性均有证据为 `PASSED`；可复现的错误 API、错误引擎绑定或兼容性破坏为 `FAILED`；缺少真实引擎验证或关键证据不足为 `INCONCLUSIVE`。预期的无效查询被正确拒绝属于通过证据。

## Boundaries

- 首轮只覆盖内置引擎类；项目脚本 `class_name` 类和自定义扩展类不在范围内。
- 本 Mission 独立于[编辑器级定向诊断](../targeted-editor-diagnostics/brief.md)，两者没有约定的先后依赖或共同验收门槛。
- 保留现有引擎选择语义及已接受的 CLI 优先行为。MCP、Pi 新接口和全局安装更新不是本 Mission 的必需交付。
- 验证使用可控项目或隔离副本，保留原项目改动，不使用真实玩家存档；不将本功能扩展成全库重构。
- 不指定查询内部实现、缓存方式或性能门槛；执行者根据实际引擎和仓库证据选择实现路线。
